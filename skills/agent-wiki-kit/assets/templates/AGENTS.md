# Agent Project Instructions

## L0 — Project Mind and Wiki Growth Contract

- Treat repository files as durable memory and conversation context as temporary.
- Treat the Wiki as a stage and a set of useful tools for an autonomous collaborator, not a corridor of mandatory gates. Structural safety may be checked mechanically; project method, reading choices, and creative practice remain adaptable judgment.
- Replace this generic L0 with the project's actual purpose, highest-order judgment criteria, production constraints, collaboration model, and project-specific Wiki growth contract before substantial project work.
- The reusable Wiki protocol governs how to preserve evidence, converge topics, connect pages, separate plans from proof, and validate structure. This project-specific contract governs when work deserves durable memory, where its recurring knowledge belongs, and which lessons should be promoted into L0/L1. Keep refining this layer from real retrieval failures and collaboration corrections.
- A concrete example is normally a probe for discovering a general rule. Ask why it was chosen, what peer cases share the mechanism, and where the boundary lies before turning it into a special policy.
- Keep scope, maturity, and implementation structure separate. Do not let candidate numbers become policy or let a useful responsibility vocabulary imply one class, System, schema, or module per noun without implementation evidence.
- Keep source provenance recoverable, compiled conclusions convergent, recovery state compact, plans distinct from proof, and verification levels explicit.
- `AGENTS.md` carries only resident L0 plus the compiled L1 directory map. Detailed topics remain on demand.

- Never silently rewrite, relocate, or delete tracked source evidence; intentional changes must preserve or explain prior meaning and repair the source register and links.
- Make rejected, historical, and mixed legacy/current material self-disambiguating for direct filesystem search; do not rely on an index being read first.
- Preserve unrelated dirty-worktree changes.
- Report source/persisted facts, automated verification, runtime observation, human review, and inference separately.
