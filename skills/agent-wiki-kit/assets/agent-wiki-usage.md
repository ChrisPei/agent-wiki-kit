## Agent Wiki Usage

The Agent Wiki is the repository's project-level memory and decision-retrieval system. It is not a mandatory reading checklist, and it does not replace source code, runtime state, tests, or human acceptance.

Its update prompt has two layers: the reusable protocol defines evidence, knowledge-plane, convergence, linking, and validation rules; the project-specific growth contract in this file defines which events deserve memory, how this project's categories and scopes are organized, and which repeated lessons should be promoted into resident context. Evolve the second layer as the project teaches better retrieval and collaboration patterns.

These are judgment aids, not creative handcuffs. Use ordinary search, file listing, direct reading, or any better retrieval method that fits the task. Tools diagnose mechanically visible risks and compile context; they do not prescribe the Agent's reasoning path.

- Root `AGENTS.md` holds resident project judgment, Wiki usage, and the compiled directory guide. `llm-wiki/agent.md` explains the reusable protocol; `llm-wiki/index.md` is a detailed optional router; `llm-wiki/wiki/` holds maintained conclusions; `llm-wiki/work/current-state.md` and its sibling work files hold recovery and recent evidence; `llm-wiki/plans/README.md` routes executable intent and acceptance gates; and `llm-wiki/raw/` plus the source register preserve provenance. Implementation and verification artifacts remain the authority for what actually works.
- Use `startup --root .` when a recovery snapshot would help. Treat its entries and the directory guide as navigation aids: choose further reads yourself from current state, plans, the detailed index, the protocol, topics, sources, or implementation according to the task, existing context, risk, and uncertainty.
- After updating the knowledge that actually owns a conclusion, run `check --root .`. Treat its format, link, relationship, scope, source-change, and directory-summary findings as diagnostics: inspect and fix what is real, then run `build-agent-context --root .` to acknowledge the reviewed directory changes and refresh this file's compiled guide.
- Before promoting a conclusion, distinguish where it applies from how mature it is. Numeric budgets, taxonomies, and named architecture responsibilities remain hypotheses until evidence or an explicit decision accepts them. If current and legacy material share a page, make that boundary visible in the summary and every affected heading; use reciprocal `supersedes` / `superseded_by` links when separate pages replace one another.
- Do not edit the generated directory guide directly. Do not silently overwrite, relocate, or delete source evidence. Intentional corrections, version updates, moves, redactions, or removals must preserve or explain prior meaning, update the source register and affected links, and record why.
