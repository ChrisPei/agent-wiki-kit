# Configuration Reference

The helper reads `agent-wiki.config.json` from the target project root. Paths are project-relative and use `/` separators.

## Example

```json
{
  "version": 1,
  "layout": "custom",
  "wikiRoot": "docs/knowledge",
  "agentGuide": "docs/knowledge/agent.md",
  "index": "docs/knowledge/index.md",
  "currentState": "docs/knowledge/work/current-state.md",
  "log": "docs/knowledge/work/log.md",
  "archiveDir": "docs/knowledge/work/log-archive",
  "plansRoot": "docs/knowledge/plans",
  "topicRoots": ["docs/knowledge/topics"],
  "rawRoots": ["docs/knowledge/raw"],
  "recoveryCandidates": [
    "AGENTS.md",
    "docs/knowledge/work/current-state.md",
    "docs/knowledge/plans/README.md"
  ],
  "contextCompiler": {
    "enabled": true,
    "target": "AGENTS.md",
    "roots": ["docs/knowledge"],
    "metadataFile": ".wiki-meta.json",
    "heading": "## Agent Wiki Directory Guide",
    "notice": "> This section is generated by Agent Wiki Kit from directory metadata. Edit `.wiki-meta.json` and rebuild instead of editing the directory list."
  },
  "budgets": {
    "indexMaxLines": 160,
    "currentStateMaxLines": 120,
    "recentLogMaxLines": 180,
    "recentLogTargetEntries": 10,
    "recentLogMaxEntries": 12,
    "topicPageMaxLines": 320
  },
  "metadata": {
    "requiredTopicFields": [
      "status",
      "owner",
      "last_updated",
      "confidence",
      "summary",
      "source_refs",
      "related_pages",
      "standalone"
    ],
    "staleAfterDays": 120,
    "currentStateStaleAfterDays": 30
  },
  "logOrder": "oldest-first"
}
```

## Fields

- `wikiRoot`: root used for Markdown scanning and wiki-style links.
- `agentGuide`: project-specific wiki protocol or scoped instructions.
- `index`: primary retrieval router.
- `currentState`: compact recovery router.
- `log`: structured recent chronology.
- `archiveDir`: monthly log archives and generated archive index.
- `plansRoot`: active and historical execution plans. New scaffolds keep this plane under the Wiki root; adopted repositories may preserve an established external root.
- `topicRoots`: directories whose Markdown files receive topic metadata and size checks.
- `rawRoots`: source/provenance roots excluded from compiled-topic checks and watched for non-additive Git changes. Such changes produce review diagnostics rather than assuming every source is universally immutable. For a `docs/wiki` layout, the source layer may be the sibling `docs/raw` directory.
- `recoveryCandidates`: recovery clues that must exist and be discoverable from root instructions. `startup` renders them in stable configuration order, but the Agent decides which ones the current task needs. Version 1 still accepts the former `requiredStartupFiles` field so existing repositories can migrate without a flag day.
- `contextCompiler.enabled`: opt into directory-metadata compilation. Existing adopted repositories remain disabled until their L0, semantic directories, and metadata have been intentionally designed.
- `contextCompiler.target`: root instructions file that receives the bounded L1 directory guide.
- `contextCompiler.roots`: ordered project-relative roots rendered into the directory tree. Adoption seeds this with the detected Wiki root even while compilation remains disabled, so later enablement starts from the real layout rather than the default scaffold.
- `contextCompiler.metadataFile`: fixed metadata file name used in every compiled directory.
- `contextCompiler.heading`: unique level-two Markdown heading used as the natural start boundary.
- `contextCompiler.notice`: single-line explanation rendered under the heading; the next standalone `---` after the heading is the natural end boundary.
- `budgets`: hot-document and topic thresholds.
- `metadata`: required topic fields and review-age warnings.
- `logOrder`: use `oldest-first` for append-at-bottom logs or `newest-first` for prepend-at-top logs. Mixed order is invalid because an archiver cannot safely infer which entries are recent.

Topic contracts may also use optional free-text `scope` and reciprocal `supersedes` / `superseded_by` references. They are intentionally not required by the default configuration: `list-topics` exposes them when present, and `check` warns about broken or one-sided replacement relationships without pretending to decide semantic authority.

## Existing repositories

Start with:

```powershell
node <skill-path>/scripts/wiki-kit.mjs doctor --root D:\Project
node <skill-path>/scripts/wiki-kit.mjs adopt --root D:\Project --check --json
node <skill-path>/scripts/wiki-kit.mjs adopt --root D:\Project
```

Auto-detection infers log order and only carries topic metadata fields already used by a strong majority of the detected topic pages. Review the preview before writing it. Remove a `topicRoot` if it contains historical/source files that do not follow one contract. Add metadata fields only when the repository has actually adopted them.

Do not mark a mutable generated directory as a `rawRoot`. Do not weaken source protection merely to make a dirty report pass; correct the classification or preserve the source.

Before enabling `contextCompiler` in an adopted repository, read `context-compilation.md`, establish the actual project-shaped directories, add metadata, and run `build-agent-context --check`. The build command edits only the section bounded by the configured directory-guide heading and its closing Markdown separator, but enabling it without designing the tree will only compile a misleading scaffold.
